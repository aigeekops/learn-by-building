# 动手学 · Learn by Building 开发约定

改动前先看对应模块，再动手。下面的条目按模块列出必须守住的约束。

## 模块与约束

- Complete learning app: `web/learning-app/`, `config/learning_app_catalog.json`, `scripts/build_learning_app.py`. These are repository-owned sources promoted after the five course/layout chats completed. Build from these sources and current public catalogs; never depend on desktop visualization folders or read runtime records. Preserve the existing route/task/lesson IDs, browser namespaces, compare-and-swap writes, receipts and 1–366 day personal plans. Reuse the existing delivery transforms for authored courses; do not inject an already integrated page. The learning app is the public site's root `index.html`; `learning/` keeps an identical copy, the alias HTML and index must match, runtime assets stay local, and `standalone.html` remains self-contained. The legacy workbench page is no longer published; original workbench Python/7–14 day behavior stays intact in source for local use. See `docs/learning-app.md` for ownership and checks.

- Site-wide routes: `web/site-route.js` / `.css`, `radar/routes.py`; only robotics and agent. Keep `RAW` complete and project `S` for the active route. Never save the filtered source list over global configuration. Plan activation, journal drafts, reviews and timer attribution must preserve route history. Electronics modes remain inside robotics.
- Navigation: electronics interactions and EE theory are children of the learning route, not standalone sidebar tabs. Keep legacy `#guides` / `#textbook` links working, highlight Learning Paths for these pages, and retain stage-specific return links.
- Unified learning delivery: use `scripts/refresh_learning_delivery.py` to stage the latest unintegrated map plus all current courseware, then validate and use `--publish` to synchronize the three allowlisted deliverables, including both `learning-map-courses-integrated.html` copies. Do not deliver only `output/learning-unified-20261108/index.html`. Preserve the raw layout and public record-engine snapshots in `research/learning-map-20261108/layout-source/`; never feed an already integrated page back into raw injection. Course directories use a compact header, one primary action and visible lesson list; course counts, start actions and lesson tabs stay in the content area; keep tab lookup rooted at the app for consistent navigation.
- Static public site: `scripts/build_static.py` promotes the learning app to the root `index.html` and keeps `learning/` as an identical copy; only the root entry may receive an opt-in deploy analytics tag, while `standalone.html` stays free of external scripts. Never publish the legacy workbench page or copy local runtime data into `dist/`. Runtime: `web/static-records.js` (IndexedDB with compare-and-swap commits), `web/static-plan.js` (must match Python pacing). Preserve v1 receipts/backups and honest seconds. Personal curriculum edits preserve stable IDs/history and live only in the browser.
- UI: `web/app.js`, `web/dashboard.js`, `web/style.css`; HTTP validation: `server.py`.
- 2026 AI courseware: `config/ai_courses.json`, `web/ai-course-models.js`, `web/ai-courses.*`. Use published 2026 official materials; keep unreleased topics pending, and distinguish original samples from completed official lectures. Preserve source/page/timestamp/access status and the separate role of unofficial Chinese indexes. Trace playback uses local computations; fixed Agent decisions and in-memory tools are explicitly labeled. Never infer mastery, add study time, or turn browser drafts into completed evidence. Package only allowlisted original code and public metadata; raw slides/transcripts and personal records stay outside the public build. Keep the source code excerpt consistent with actual model conditions.
- Daily study completion: `radar/study.py` (atomic, idempotent receipts); timer state stays in browser storage.
- Automatic journal: `web/automatic-journal.js`, `radar/journal.py`. Record only explicit visits, answers and objective model operations; never render/animation frames. Timed sessions write their journal in the same transaction as time and receipts; sub-minute sessions keep seconds without rounding up minutes. Keep `auto-` records immutable on automatic retries, including after user edits/archive. Pending browser events retry without re-rendering labs. Keep manual thoughts optional and model results distinct from hardware evidence. No schema changes are required for automatic entries; existing v1 backups include them.
- Immersive site frame: `web/immersive.js` / `.css`, loaded after app.js / other styles. Regular layout is the default; the persistent one-click immersive toggle moves existing nodes without losing inputs or timers. In immersive mode the sidebar lives in an accessible drawer; today/course/records are primary. Show one current course block, retain full directory and route-specific position. Navigation and current-block selection never certify completion. Preserve exercise DOM and timer while syncing the shell.
- Optional author invitation: `web/author.json`, `web/wechat-follow.js` / `.css`. Keep it at the course-block end and footer, never auto-open or gate access. Use only a verified original account QR at `web/assets/wechat-qr.jpg`; empty/missing assets fall back to name search. Public account configuration contains no credentials. Forks should replace or disable the author's branding.
- First-use settings and one daily entry: `web/workspace-tools.js`. Record backups: `radar/backup.py`; preview is read-only, restore validates both file and current-record hashes, writes a safety backup before atomic replacement, and preserves both routes and idempotency receipts. Test only against temporary data. Scope excludes config, credentials and browser state. Third-party courses, textbooks and images keep their own rights, separate from project MIT.
- Personal plans: `radar/plans.py`, `web/personal-plan.js`; deterministic preview before adoption, preserve history. Check-ins reuse atomic study receipts, no fabricated minutes or mastery. New UI plans default to explicit `progression: current`; legacy requests that omit it retain sequential behavior and profile shape. Current-block mode does not certify readiness or advance the block.
- Beginner companion: `config/electronics_beginner.json`, `web/electronics-beginner.js` / `.css`; optional stage-zero LED: `web/electronics-basics.js`. Steps and quizzes are navigation and feedback, never completion; keep presets consistent with the displayed model.
- Extra teaching models: `web/electronics-models.js`; exercises: `web/electronics-lessons.js` / `.css`. All six model/inspection lessons are original topic exercises, not literal book experiments. Keep unknown electrical states unknown, refuse unsafe meter models, and never convert preset cases to hardware evidence.
- Content scope: website basics stay open; do not add membership, purchase verification or paywalls. Public deployment uses browser-local records; never publish the local Python data store.
- EE textbook companion: `config/ee_textbook.json`, `web/ee-textbook.js` / `.css`; 24 original guides and a six-volume chapter index, not a full translation. Progress uses validated `tasks.ee_lesson` plus saved evidence; do not infer mastery from a quiz or borrow `electronics_unit` outcomes. Source attribution stays separate from project MIT.
- Robotics curation: `config/robotics_curriculum.json`, `web/robotics-curriculum.js` / `.css`; 24 blocks reuse stable month ids and companion modules. Keep source access/version caveats, original resource directories, and blank task evidence. Month jumps must expand their details element. Ordered reading steps carry direct chapter links; remediation may only point to earlier blocks. A first-step task keeps blank evidence and uses at most the current daily budget or 45 minutes.
- Robotics foundation courseware: `config/robotics_foundations_*.json`, `web/robotics-foundations*`, `scripts/build_robotics_foundations.py`. Five topics reuse map IDs `mit2007`, `modern`, `pid`, `kalman`, `ros`; preserve original teaching entrances and stored plans. Future-plan lesson ordinals and direct sample entrances must resolve to the new lesson, while explicit original-unit clicks retain original content. Models are pure self-contained functions, SVG frames and downloadable code use the same calculation, and drafts use one storage key per lesson. Keep ROS/Gazebo target-environment execution separate from offline arithmetic and static package checks. Refresh the existing draft incrementally with a hash check and backup; later AI refreshes must preserve authored robotics content and its future-plan definitions.
- Course expansion programs: `scripts/course_programs.py` embeds only explicitly allowlisted original Python files into foundation/application lessons. Keep downloads available offline and keep program source, displayed commands and execution status consistent. The six-course November expansion is documented in `docs/course-expansion-2026-11-09.md`; CPU PyTorch/Gloo receipts do not establish CUDA multi-GPU performance, and generated CAD/BOM files keep physical acceptance measurements blank.
- Map availability: `web/course-map-status.js` / `.css`, `scripts/sync_course_map.py`. Derive authored lesson counts from the current AI, foundation and robotics catalogs. Mark legacy prerequisite exercises separately from authored courseware; leave unmade branches pending. Overview group counts, expanded course cards, search and first-lesson links must agree. Content readiness never changes personal learning progress or records. `build_teaching_preview.upgrade_course_cards` retains the marked status adapter on later course refreshes.
- Mathematics and ML batch: `config/foundation_{linear,probability,cs229}.json`, `web/foundation-math.js`, `web/foundation-math-scenes.js`, `examples/foundation-math/`. Reuse map IDs and the foundation reader, keep the 18 stable lesson IDs, and preserve exact model/diagram/code correspondence. Static geometry remains static; iterative algorithms show actual recorded updates. Known-sigma normal intervals and exact binomial tails retain their stated assumptions; undefined results remain explicit. New public plan estimates follow current lesson IDs without changing adopted plans. See `docs/map-math-batch2.md`.
- Beginner-first applies sitewide: `config/agent_curriculum.json` uses the same renderer and plan generator as robotics. Both routes have 24 blocks with prerequisites, plain-language intuition, three concrete practice steps, acceptance, earlier remediation and optional depth. Prefer a coherent teaching course over a reference directory; electronics starts with Make: Electronics, AAC supplies theory. Optional `walkthrough` lessons provide original examples, expected results, explanations and independent exercises; `bridge` teaches missing prerequisites. Keep `lesson` as the existing EE lesson id. Execute original Python examples and check electrical expectations against the actual models. New short plans use `curriculum:<block-id>` and editorial `study_load` estimates to pace practice by daily budget, with a minimum three practice days per block and retrieval every seventh day. Estimates are not observed learning times. Starting blocks remain explicit; experience labels never silently skip prerequisites. Preserve all legacy plan metadata and evidence. Calendar dates and task completion do not certify knowledge.
- Route companions: `config/learning_links.json`, `web/learning-links.js` / `.css` connect roadmap stages, EE lessons, labs and plan units. Shared lessons retain their invoking stage; stage drafts contain no completed evidence. New plan tasks use mapped stages; never rewrite historical plans.
- Goal routes: `config/electronics_paths.json`, `web/learning-paths.js`; RC animation: `web/rc-lab.js`.
- Community participation: `radar/community.py`, `config/community.json`, `web/community.js` / `.css`. Only allow canonical GitHub repository links, expose Discussions only when configured, and keep empty configuration visibly unconnected. Drafts include public course metadata only; never prefill personal tasks, notes or credentials. Users publish manually on GitHub. Templates and setup live in `.github/` and `COMMUNITY.md`; template files do not prove remote activation. Use isolated config as well as isolated data for browser settings tests.
- Learning journal: `radar/journal.py`, `web/journal.js`, `web/journal.css`; interactive DC model: `web/electronics-lab.js`, `web/electronics-lab.css`; curated guides: `config/guides.json`, `web/assets/`.
- Journal entries live in local SQLite in the Python app, or browser-local IndexedDB in the static app. Never seed plans or generated text as completed experiments. Keep calculation, simulation and hardware evidence explicit. Journal writes do not add study minutes; use the existing session workflow.
- SQLite storage, config loading and URL validation: `radar/core.py`.
- Curriculum: `config/roadmaps.json`.
- 运行数据只查计数和聚焦样例，不要整体读入。
- Run tests matching the changed behavior; full standard-library suite is small: `python3 -m unittest discover -s tests -v`.

## Runtime invariants

- Per-course calculation inspectors: `web/course-inspectors/<courseId>.js`, `web/course-inspector.*`, `scripts/course_inspectors.py`. Each of the 26 authored courses owns its equations, cells and actual before/after checks; follow `docs/course-inspectors/CONTRACT.md`. Keep original figures and real playback, preserve IDs/drafts/receipts, and never derive completion or minutes from inspection. Full builds require all providers; `LBB_ALLOW_PARTIAL_INSPECTORS=1` is for temporary development previews only. `node scripts/check_course_inspectors.cjs --report docs/course-inspectors/coverage.json` checks all course/model/frame/control-boundary coverage against current catalogs before delivery.

- Ten added course companions: `config/extension_*.json`, `web/extension-course-*.js`, `web/extension-draft-integration.js`, `scripts/integrate_extension_draft.py`. Author with `scripts/author_extension_courses.cjs` and its `course-authoring/` sources. Keep all ten existing map IDs, authored lesson IDs, original prerequisite entrances, shared drafts and adopted personal plans. The eight-lesson courses are original topic selections, not complete translations or unpublished official units. Node examples must match displayed code; Arduino target compilation, ROS/MoveIt execution and real LeRobot training remain separate from finite browser calculations. Refresh public delivery through `refresh_learning_delivery.py`; counts derive from catalogs. Run extension arithmetic/integration tests and isolated desktop/mobile offline/HTTP browser QA when changing these modules.

- Learning app inner pages keep only global navigation in the sidebar; course directories belong in the content area. Course/lesson topbars contain breadcrumbs and existing route selection only. Keep course counts, start actions and the single lesson tablist in the content area below its title; do not duplicate breadcrumb return links in the body. Run shared shell updates before course-specific chrome, and keep focus timing in normal workspace flow without overlaying content.
- Choose teaching presentation by the concept. Coding snapshots expose assignments, scopes and return values; static calculations must not acquire artificial playback. Do not add looping token flashes, flowing dashes or per-frame fades without a learning purpose. Preserve real state evolution for algorithms and physical models.
- Course animation readers use a bounded side-by-side workspace: animation and playback on the left, current code, explanation and variables on the right. Keep the desktop workspace within the available viewport; long code/values scroll inside their pane. Narrow screens keep the two columns with workspace-only horizontal scrolling. Variable arrays stay compact (flat arrays on one line, nested arrays or records one group per row), never deep pretty-printed one character per line.
- UI rendering, CRUD, progress, search and filtering never call a model or reach the network.
- Keep Python runtime standard-library only unless a dependency has a concrete justified benefit.
- No unbounded retry loops; every write path stays atomic and idempotent.
