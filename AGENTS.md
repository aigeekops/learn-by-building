# 动手学 · Learn by Building 开发约定

改动前先看对应模块，再动手。下面的条目按模块列出必须守住的约束。

## 模块与约束

- Site-wide routes: `web/site-route.js` / `.css`, `radar/routes.py`; only robotics and agent. Keep `RAW` complete and project `S` for the active route. Never save the filtered source list over global configuration. Plan activation, journal drafts, reviews and timer attribution must preserve route history. Electronics modes remain inside robotics.
- Navigation: electronics interactions and EE theory are children of the learning route, not standalone sidebar tabs. Keep legacy `#guides` / `#textbook` links working, highlight Learning Paths for these pages, and retain stage-specific return links.
- Static public site: `scripts/build_static.py` allowlists assets and public configs; never copy local runtime data into `dist/`. Runtime: `web/static-records.js` (IndexedDB with compare-and-swap commits), `web/static-plan.js` (must match Python pacing). Preserve v1 receipts/backups and honest seconds. Personal curriculum edits preserve stable IDs/history and live only in the browser.
- UI: `web/app.js`, `web/dashboard.js`, `web/style.css`; HTTP validation: `server.py`.
- Daily study completion: `radar/study.py` (atomic, idempotent receipts); timer state stays in browser storage.
- Automatic journal: `web/automatic-journal.js`, `radar/journal.py`. Record only explicit visits, answers and objective model operations; never render/animation frames. Timed sessions write their journal in the same transaction as time and receipts; sub-minute sessions keep seconds without rounding up minutes. Keep `auto-` records immutable on automatic retries, including after user edits/archive. Pending browser events retry without re-rendering labs. Keep manual thoughts optional and model results distinct from hardware evidence. No schema changes are required for automatic entries; existing v1 backups include them.
- Immersive site frame: `web/immersive.js` / `.css`, loaded after app.js / other styles. Regular layout is the default; the persistent one-click immersive toggle moves existing nodes without losing inputs or timers. In immersive mode the sidebar lives in an accessible drawer; today/course/records are primary. Show one current course block, retain full directory and route-specific position. Navigation and current-block selection never certify completion. Preserve exercise DOM and timer while syncing the shell.
- Optional author invitation: `web/author.json`, `web/wechat-follow.js` / `.css`. Keep it at the course-block end and footer, never auto-open or gate access. Use only a verified original account QR at `web/assets/wechat-qr.jpg`; empty/missing assets fall back to name search. Public account configuration contains no credentials. Forks should replace or disable the author's branding.
- First-use settings and one daily entry: `web/workspace-tools.js`. Record backups: `radar/backup.py`; preview is read-only, restore validates both file and current-record hashes, writes a safety backup before atomic replacement, and preserves both routes and idempotency receipts. Test only against temporary data. Scope excludes config, credentials and browser state. Third-party courses, textbooks and images keep their own rights, separate from project MIT.
- Personal plans: `radar/plans.py`, `web/personal-plan.js`; deterministic preview before adoption, preserve history. Check-ins reuse atomic study receipts, no fabricated minutes or mastery. New UI plans default to explicit `progression: current`; legacy requests that omit it retain sequential behavior and profile shape. Current-block mode does not certify readiness or advance the block.
- Beginner companion: `config/electronics_beginner.json`, `web/electronics-beginner.js` / `.css`; optional stage-zero LED: `web/electronics-basics.js`. Steps and quizzes are navigation and feedback, never completion; keep presets consistent with the displayed model.
- Extra teaching models: `web/electronics-models.js`; exercises: `web/electronics-lessons.js` / `.css`. All six model/inspection lessons are original topic exercises, not literal book experiments. Keep unknown electrical states unknown, refuse unsafe meter models, and never convert preset cases to hardware evidence.
- Content scope: website basics stay open; do not add membership, purchase verification or paywalls. Public deployment uses browser-local records; never publish the local Python data store.
- EE textbook companion: `config/ee_textbook.json`, `web/ee-textbook.js` / `.css`; 24 original guides and a six-volume chapter index, not a full translation. Progress uses validated `tasks.ee_lesson` plus saved evidence; do not infer mastery from a quiz or borrow `electronics_unit` outcomes. Source attribution stays separate from project MIT.
- Robotics curation: `config/robotics_curriculum.json`, `web/robotics-curriculum.js` / `.css`; 24 blocks reuse stable month ids and companion modules. Keep source access/version caveats, original resource directories, and blank task evidence. Month jumps must expand their details element. Ordered reading steps carry direct chapter links; remediation may only point to earlier blocks. A first-step task keeps blank evidence and uses at most the current daily budget or 45 minutes.
- Beginner-first applies sitewide: `config/agent_curriculum.json` uses the same renderer and plan generator as robotics. Both routes have 24 blocks with prerequisites, plain-language intuition, three concrete practice steps, acceptance, earlier remediation and optional depth. Prefer a coherent teaching course over a reference directory; electronics starts with Make: Electronics, AAC supplies theory. Optional `walkthrough` lessons provide original examples, expected results, explanations and independent exercises; `bridge` teaches missing prerequisites. Keep `lesson` as the existing EE lesson id. Execute original Python examples and check electrical expectations against the actual models. New short plans use `curriculum:<block-id>` and editorial `study_load` estimates to pace practice by daily budget, with a minimum three practice days per block and retrieval every seventh day. Estimates are not observed learning times. Starting blocks remain explicit; experience labels never silently skip prerequisites. Preserve all legacy plan metadata and evidence. Calendar dates and task completion do not certify knowledge.
- Route companions: `config/learning_links.json`, `web/learning-links.js` / `.css` connect roadmap stages, EE lessons, labs and plan units. Shared lessons retain their invoking stage; stage drafts contain no completed evidence. New plan tasks use mapped stages; never rewrite historical plans.
- Goal routes: `config/electronics_paths.json`, `web/learning-paths.js`; RC animation: `web/rc-lab.js`.
- Community participation: `radar/community.py`, `config/community.json`, `web/community.js` / `.css`. Only allow canonical GitHub repository links, expose Discussions only when configured, and keep empty configuration visibly unconnected. Drafts include public course metadata only; never prefill personal tasks, notes or credentials. Users publish manually on GitHub. Templates and setup live in `.github/` and `COMMUNITY.md`; template files do not prove remote activation. Use isolated config as well as isolated data for browser settings tests.
- Learning journal: `radar/journal.py`, `web/journal.js`, `web/journal.css`; interactive DC model: `web/electronics-lab.js`, `web/electronics-lab.css`; curated guides: `config/guides.json`, `web/assets/`.
- Journal entries live in local SQLite in the Python app, or browser-local IndexedDB in the static app. Never seed plans or generated text as completed experiments. Keep calculation, simulation and hardware evidence explicit. Journal writes do not add study minutes; use the existing session workflow.
- SQLite storage, config loading and URL validation: `radar/core.py`.
- Curriculum: `config/roadmaps.json`.
- 运行数据只查计数和聚焦样例，不要整体读入。
- Run tests matching the changed behavior; full standard-library suite is small: `python3 -m unittest discover -s tests -v`.

## Runtime invariants

- UI rendering, CRUD, progress, search and filtering never call a model or reach the network.
- Keep Python runtime standard-library only unless a dependency has a concrete justified benefit.
- No unbounded retry loops; every write path stays atomic and idempotent.
